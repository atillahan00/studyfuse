# Known limitations — read before relying on an archive

- **Office/OneNote/HTML/EPUB/SVG/TIFF are not natively rendered.** The implemented fallback retains each original, explains the source-app PDF conversion, and accepts a replacement at the same position. Without a replacement, the output contains a warning page and is marked incomplete. Therefore the raw Office acceptance batch is not automatic end to end; the documented PDF export step is required.
- Source application exports can crop infinite canvases or omit comments, notes, hidden slides/sheets, attachments, animations and off-page content. StudyFuse cannot recover material already missing from that export. A SHA-256 proves byte identity, not completeness of the teacher's notebook.
- PDF output preserves the visual source view in the MediaBox/CropBox union. Content entirely outside both boxes is not discovered automatically. PDF portfolios, active media, scripts, interactive forms, signatures and original navigation semantics are not reproduced as equivalent live features. Original files remain available. Layers and embedded attachments cause a review status.
- Annotation appearance streams are flattened. Missing visible appearances fail explicitly; hidden annotations and textual comments are reported. Highly unusual annotation transforms, blend modes, custom fonts or malformed PDF constructs still need visual inspection. The PDFBox Android port is an older upstream and not a newly audited general-purpose sandbox for hostile PDFs.
- Long-page splitting uses whitespace and overlap, not semantic understanding of handwriting, equations, tables or diagrams. It may split a large diagram. Both axes tile if necessary. Known embedded font sizes guide readability; image text/handwriting size cannot be guaranteed. Original-size mode deliberately does not paginate or enlarge source content.
- A clipped vector form retains the original text operators. Some PDF text extractors ignore clipping and repeat off-page text on multiple generated pages. The report warns on tiled vector pages. Visual boundaries are authoritative; this is a limitation of extraction interoperability, not missing visible source content. Overlap intentionally duplicates a small visible boundary region.
- OCR is bundled **printed Latin** text recognition, optional and unverified. It does not provide reliable handwriting or mathematics recognition, guaranteed reading order or verified accuracy. Available raw line/word confidence scores are retained in JSON (not interpreted as proof); the engine supplies no page-level score. OCR is appended as explicitly labelled searchable text; it is not an invisible, verified text layer attached to every visual word. Unsupported OCR glyphs are shown as Unicode codes in the PDF, while raw text stays in JSON. Original handwritten images are untouched.
- UTF-8 text, Markdown and CSV are literal text reflow, not Office/Markdown/HTML layout engines. Glyph coverage is Noto Sans plus Noto Sans Math; unsupported text glyphs or invalid encoding fail rather than disappearing. Complex-script shaping, colour emoji and arbitrary fonts are not implemented.
- Image codec availability is device-dependent. Large-region/whole-image memory guards can require an external PDF conversion, particularly for unsupported regional HEIC/BMP decoding and very large original-size images. Lossless bitmap encoding preserves decoded resolution, not all original colour profiles/metadata. Images use a nominal 150 DPI for physical layout; EXIF print-density metadata is not used. Exact originals remain saved.
- JPX/JBIG2 encoded images remain in the vector PDF, but the bundled PDFBox raster verifier cannot decode them. Those sources receive REVIEW status and require external/native visual inspection. Oversized embedded images also skip raster verification with REVIEW status to protect memory.
- PDFBox uses disk scratch for streams, but the complete assembled PDF's page/resource metadata remains in memory. File count has no artificial cap; available RAM, disk, codec limits and Android background quotas are real limits. Arbitrary gigabyte documents and every malformed file cannot be certified by this test suite.
- Output-size estimates before conversion are not reliable; the UI shows source total and explains that limitation. Volumes are split by measured size and page boundaries, which may yield more volumes than optimal. A single oversized page is retained and warned about. All printed numbers refer to the full document; standalone volumes do not duplicate the table of contents or rebuild bookmarks.
- WorkManager recovers by restarting from originals rather than resuming a partially converted page. Android 15 foreground limits and Android 16 job quotas can stop very long work; retry is available. Force-stopping the app, OEM battery policies and low storage can interrupt processing. A cancelled job does not intentionally publish a partial PDF.
- Folder order is recursive, name-sorted traversal; Android does not promise provider enumeration order or the user's tap order. Once imported, StudyFuse preserves the explicit project order. Empty/unreadable provider folders may have provider-specific behaviors.
- The archive is an ordinary PDF, not certified PDF/A. Page numbers and reports are generated content in reserved borders; original-size pages gain a border. AI Study and Archive modes share the visual conversion pipeline.
- No physical tablet or Android 15/16 emulator was connected in the build environment. Robolectric exercises API 34 UI/database/processing logic, with independent MuPDF document checks; actual platform PDF preview, native long-image decoding, OCR model behavior, external share recipients and OEM lifecycle behavior still need device QA. The connected-device test APK is supplied and compiles; it is not represented as executed.
- Debug APK signing is for evaluation. Back up saved PDFs and reports before uninstalling or switching signing keys. Private project backup/export as a restorable project package and database migrations beyond schema 1 are not implemented.
