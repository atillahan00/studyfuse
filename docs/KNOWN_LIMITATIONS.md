# Known limitations — read before relying on an archive

- **Local visual AI is a reviewable draft, not certified handwriting recognition.** Version 1.2 adds real image-capable `.litertlm` execution, but model weights must be imported separately and pass the device image-input test. No compatible model or physical MagicPad 2 is connected in this build environment. German handwriting, graphs, chemical structures and mathematical signs/solutions can be misread confidently. Source quotation matching cannot prove a model's claim follows from the source. Every practice item starts unapproved; student review remains necessary. See [local AI](LOCAL_AI.md).
- Local AI vision needs a compatible GPU/runtime/model file; CPU mode changes text execution only. There is no automatic NPU acceleration. Model size, actual free RAM, driver support, context length, temperature and battery affect performance. Whole-page/overlapping-region processing reduces small-content loss but does not guarantee all marks were recognized. Processing all region requests is not proof of complete understanding.
- Enriched Learning can use explicitly selected reference documents and labelled model knowledge **offline**. It does not perform live web research or fabricate web citations. Documents Only requests source-supported material, rejects declared additions and checks evidence excerpts, but cannot mathematically guarantee absence of model hallucinations. Mode changes invalidate the visible study pack and require matching generation/review.
- Exam scope/date are optional. Without teacher instructions the model prepares broadly from the selected documents; it cannot know actual exam weighting. Review intervals are transparent heuristics, and grading is student self-assessment. There is no verified automatic marking or readiness percentage. Generated worked examples/questions depend on supporting source content and model quality.

- **Office/OneNote/HTML/EPUB/SVG/TIFF are not natively rendered.** The implemented fallback retains each original, explains the source-app PDF conversion, and accepts a replacement at the same position. Without a replacement, the output contains a warning page and is marked incomplete. Therefore the raw Office acceptance batch is not automatic end to end; the documented PDF export step is required.
- Source application exports can crop infinite canvases or omit comments, notes, hidden slides/sheets, attachments, animations and off-page content. StudyFuse cannot recover material already missing from that export. A SHA-256 proves byte identity, not completeness of the teacher's notebook.
- PDF output preserves the visual source view in the MediaBox/CropBox union. Content entirely outside both boxes is not discovered automatically. PDF portfolios, active media, scripts, interactive forms, signatures and original navigation semantics are not reproduced as equivalent live features. Original files remain available. Layers and embedded attachments cause a review status.
- Annotation appearance streams are flattened. Missing visible appearances fail explicitly; hidden annotations and textual comments are reported. Highly unusual annotation transforms, blend modes, custom fonts or malformed PDF constructs still need visual inspection. The PDFBox Android port is an older upstream and not a newly audited general-purpose sandbox for hostile PDFs.
- Long-page splitting uses whitespace, optional user-defined cuts and overlap, not semantic understanding of handwriting, equations, tables or diagrams. It may split a large diagram. Both axes tile if necessary. Known embedded font sizes guide readability; image text/handwriting size cannot be guaranteed. Original-size mode deliberately does not paginate or enlarge source content.
- A clipped vector form retains the original text operators. Some PDF text extractors ignore clipping and repeat off-page text on multiple generated pages. The report warns on tiled vector pages. Version 1.1 adds a Markdown companion that filters glyphs to visible bounds and de-duplicates overlap by source position; this does not alter the behavior of external extractors reading the PDF itself. Visual boundaries are authoritative; this is a limitation of extraction interoperability, not missing visible source content. Overlap intentionally duplicates a small visible boundary region.
- OCR is bundled **printed Latin** text recognition, optional and unverified. It does not provide reliable handwriting or mathematics recognition, guaranteed reading order or verified accuracy. Available raw line/word confidence scores are retained in JSON (not interpreted as proof); the engine supplies no page-level score. OCR is appended as explicitly labelled searchable text; it is not an invisible, verified text layer attached to every visual word. Unsupported OCR glyphs are shown as Unicode codes in the PDF, while raw text stays in JSON. Original handwritten images are untouched.
- UTF-8 text, Markdown and CSV are literal text reflow, not Office/Markdown/HTML layout engines. Glyph coverage is Noto Sans plus Noto Sans Math; unsupported text glyphs or invalid encoding fail rather than disappearing. Complex-script shaping, colour emoji and arbitrary fonts are not implemented.
- Image codec availability is device-dependent. Large-region/whole-image memory guards can require an external PDF conversion, particularly for unsupported regional HEIC/BMP decoding and very large original-size images. Lossless bitmap encoding preserves decoded resolution, not all original colour profiles/metadata. Images use a nominal 150 DPI for physical layout; EXIF print-density metadata is not used. Exact originals remain saved.
- JPX/JBIG2 encoded images remain in the vector PDF, but the bundled PDFBox raster verifier cannot decode them. Those sources receive REVIEW status and require external/native visual inspection. Oversized embedded images also skip raster verification with REVIEW status to protect memory.
- PDFBox uses disk scratch for streams, but the complete assembled PDF's page/resource metadata remains in memory. File count has no artificial cap; available RAM, disk, codec limits and Android background quotas are real limits. Arbitrary gigabyte documents and every malformed file cannot be certified by this test suite.
- Output-size estimates before conversion are not reliable; the UI shows source total and explains that limitation. Volumes are split by measured size and page boundaries, which may yield more volumes than optimal. A single oversized page is retained and warned about. All printed numbers refer to the full document; standalone volumes do not duplicate the table of contents or rebuild bookmarks.
- WorkManager reuses SHA-verified per-source conversion checkpoints. An unfinished source restarts from its original; page-level checkpoints within a single source are not implemented. Android 15 foreground limits and Android 16 job quotas can stop very long work; retry is available. Force-stopping the app, OEM battery policies and low storage can interrupt processing. A cancelled job does not intentionally publish a partial PDF.
- Folder order is recursive, natural-name-sorted traversal; Android does not promise provider enumeration order or the user's tap order. Once imported, StudyFuse preserves the explicit project order. Empty/unreadable provider folders may have provider-specific behaviors.
- The archive is an ordinary PDF, not certified PDF/A. Page numbers and reports are generated content in reserved borders; original-size pages gain a border. AI Study and Archive modes share the visual conversion pipeline.
- No physical tablet was connected in the local build environment. GitHub API 35 connected-test results are recorded for the tested commit in the validation record. Robolectric exercises API 34 UI/database/processing logic, with independent MuPDF document checks. External share recipients, model inference on real teacher documents and OEM lifecycle/thermal behavior still need device QA. Deterministic test adapters used for pipeline coverage are not neural accuracy evidence.
- Debug APK signing is for evaluation. Back up saved PDFs and reports before uninstalling or switching signing keys. Version 1.1 includes restorable project ZIPs and the schema 1→2 migration. Future CI debug artifacts may use different signing keys; optional production signing requires a privately managed persistent key.

- Backup restore creates a new project, not an overwrite of an existing one. Exported PDFs and conversion caches are not in the backup and are regenerated. Removed-source bytes and undo timestamps are included. Restore validates entries and hashes; interruption before database publication may leave private staging bytes until cleanup/project storage management.
- Companion text filtering uses glyph coordinates and approximate source-position quantization for overlap. Complex rotated/vertical text, unusual font metrics and reading order can still be imperfect. Use the visual PDF for diagrams, equations and handwritten notes. OCR remains explicitly unverified.
- The side-by-side comparison can show corresponding source regions, but PDFs whose MediaBox and CropBox differ may need the full-source view. Manual split controls operate in source PDF points; image source dimensions use the nominal 150 DPI conversion.
- Backup schema 2 includes study readings, corrections and review history; weights must be imported separately after reinstall. Study JSON entries have a 16 MiB per-entry safety bound and the archive manifest retains its 8 MiB bound. Oversized entries fail with an explicit warning rather than being omitted. Restore creates a new project and may require source PDF recompilation before matching cached study notes can be opened. Generated study exports are regenerated. The original-source PDF appendix may make exam-note exports large.
